### 5. 토큰화와 문맥 단위 구성
- 토큰화와 청크 분할은 다른 이야기
- 토큰화는 텍스트를 단어, 형태소, 문자 조각 같은 처리 단위로 나누는 작업
- 청크 분할은 문장이나 의견을 분석 목적에  맞는 덩어리로 나누는 작업
    - ex) 공백 분리(split)  
    - 형태소 분석(ex. 허리 가 꽉 끼다)
    - Ngram(ex.Ngram(2)라면 -> 허리가 낀다. 를 한 단어로 보겠다는 의미  
    - 토크나이저(모델) 

### 5-1. TF-IDF(빈도 기반)
- 텍스트를 숫자로 표현해야하는 이유
    - 숫자 특징으로  컴퓨터가 이해할 수 있게 
- 가장 쉬운 방법이 해당 단어가 해당 문서에서 얼마나 나왔는지?
    - 따라서 텍스트 분석에서 TF-IDF를 빼고 이야기하기는 어렵다.
- **TF는 한 문서에서 해당 단어가 나타나는 정도(빈도수)**
- **DF는 그 단어가 등장한 문서 수**
- **IDF는 여러 문서에 널리 등장하는 단어의 가중치를 상대적으로 낮추는 기법**

### 5-2. 임베딩 유사도 이해하기
- 임베딩은 단어 / 문장 문서를 실수로 벡터로 바꾸는 표현
- 사전 학습된 문장 임베딩 모델을 사용하면 표현이 달라도 의미가 비슷한 문장을 가까운 벡터로 배치할 수 있게 만들수 있다.
- 코사인 유사도는 두 벡터의 내적을 각 벡터 길이의 곱으로 나누 값
- 유사도 0.8은 80% 확률로 같은 의미라는 뜻은 아님, 어떤 점수부터 유사하다고 볼지는 사람이 판단한 문장 쌍으로 검증

### 6. 지도학습으로 리뷰 분류
- 지도학습: 정답이 있는 라벨로 분류(텍스트 분석에서는 주로 정답을 본인이 부여하는 식)
    - 따뜻한 촉감과 색 (명확한 기준을 세워야 정답률이 올라갈 수 있음)

- 분류 체계 확립 후 실제 사례로 정답지를 만들어가는 과정 포함
    - 우리가 저번에 샀었는 지 잘 모르겠는데 조회해보세요. 만약 제 id가 뜨면 그냥 그대로 추가 주문해주시고 만약에 제 ID가 안뜨면 신규 구매니까 신규 구매로 분류해주고 첫 구매 할인 쿠폰 적용해주세요. 첫 구매 할인 쿠폰 적용이 안되면 그냥 안살게요. 
        - 추가 주문/ 신규 구매 / 기타 (멀티 라벨)

- 임계값: 확률을 출력하는 모델은 임계값에 다라 결과가 달라질 수 있다.
    - 불만 누락을 줄이기 위해 임계값을 낮추면 Recall을 높일 수 있지만 오탐지도 늘 수 있다.

### 6-1. 정답없이  키워드로 주제 탐색하기
- 단어 빈도로 자주 언급되는 내용 확인하기
    - 좋다 <- 라는 단어로 특정 상품의 이유 분석까지 하고 싶다면 문맥도 파악해야 한다.

- 군집화: 임베딩을 만든 뒤에  K-means 등을 통해 문장을 묶을 수 있다.
    - 대표 문장과 자주 등장하는 표현을 묶어 사람이 각 군집에 이름을 부여하는 방법도 있다.
        - 0 -> 허리가 낀다 -> 허리 사이즈 불만
        - 1 -> 보푸라기 많음 -> 봉재와 마감 불만
        - 2 -> 생각보다 빨간색이 아님 -> 색상기대 불만
        - 0,1,2는 군집화 결과고 사람이 라벨링을 해줘얗하는 값

- 토픽 모델링: 토픽 모델링은 문서 집합에 나타나는 주제를 찾는 방법
    - 예를 들어 LDA는 단어 출현 통계에 기반하여  문서의 토픽 혼합을 모델링하는 방법

## LLM 분석 흐름(일반적인)
1. 문제와 평가 기준 정의 -> 2. 데이터와 정답 표본 준비 -> 3. 최소 정제와 문장 구성 확인 -> 4. 모델 및 프롬프트 선택 -> 5. 추론 실행(모델 실행) -> 6. 출력과 파싱 검증 -> 7. 평가 -> 8. 운영 및 고도화
- RAG나 Fine-Tuning은 반드시 거치는 작업은 아님 경우에 따라 사용할 수 있음
- Fine-Tuning: 내 입맛에 맞게 수정할거야

### 1. LLM이 분석 과정에서 하는 일
- 생성형 LLM은 입력 문맥과 앞서 생성한 토큰을 바탕으로 다음 토큰을 생성한다.

|관점|전통적 분류 파이프라인|LLM 활용|
|---|---|---|
|사용자 준비|특징 추출기와 분류 및 라벨|프롬프트 출력, 규격 및 평가 표본|
|입력 표현|TF-IDF, 임베딩 직접 구성|모델의 토크나이저 내부 표현 사용|
|출력|미리 정한 Y값, 특징, 점수값|라벨과 근거 및 요약 등도 같이 생성|
|학습필요성|과제별 분류 학습이 일반적|기존 모델에 지시만 주어도 시작 가능|
|주요 검증|예측 정확성과 일반화|예측 저오학성에 형식, 근거 부분, 추가 검증 추가|

- 학습과 추론: 추론은 이미 학습된 모델에 입력을 주어 결과를 만드는 과정
- 파인 튜닝은 별도의 학습과정으로 모델 파라미터 일부 또는 전체를 업데이트 하는 방법
- **예시를 넣었다는 것으로 파인튜닝했다고 주장하면 틀린다.**

- 구체적인 질문은 구체적인 답변을 만든다.
    - '이 리뷰 분석해줘' -> ?
        - 감정, 키워드, 요약, 근거? 무엇이 필요한지 불명확하다.
        - '리뷰를 의견 단위로 나누고 각 의견이 속성, 감정, 원문 근거를 반환해주세요'와 같이 출력 조건을 구체화하는 것이 좋다.

- 원문 보존은 필수
- LLM 전처리는 쵯소한부터 최대한까지

- 청크 분할/ 입력 문맥 구분
    - 청크 목적 구분하기
    - 의견 분석용 청크는 서술 내용을 보존해야함
    - 검색용 청크 분석은 긴 문서에 관련 부분을 찾고 모델 입력에 제한 안에 넣기 위해 나눔

- 입력 문백 구분
    - 디자인은 예쁜데, 허리가 꽉 끼는 편, 그래서 집에서만 입는데 편하긴해요.
        - 첫 부분은 디자인에 대한 긍정, 두 번째 부분은 부정, 마지막 부분은 긍정
        - 편하게, 잘 입어요를 분리해 긍정 의견으로 볼 수도 있고 하나로 합쳐서 문맥을 파악하여 하나의 긍정문으로 볼 수도 있다.

### 2. 프롬프트
- 지시와 데이터 구분
- 프롬프트는 수행할 과제, 판단 기준, 입력 데이터, 출력 형식, 예외 처리를 포함한다.
- '~해줘'보다는 무엇을 근거로 어떤 값을 출력해야하는 지 구체적으로 정하는 것이 좋다.

    1. 불만은 명시된 부정(1)을 분석해야 한다.
    2. 긍정과 부정이 섞여서 혼재한다면 불만이  있음으로 판단한다.
    3. 두께나 길이를 단순 나열한다면 부정으로 판단하지 않는다.
    4. 속성은 디자인, 색상, 사이즈, 활용성, 퀄리티, 가격 중에 하나를 선택한다.
    5. 근거는 원문에 내용을 참고하여 작성하고 실제 존재하는 문장 원문을 그대로 이용한다.
    6. 판단이 불가한 경우는 False라는 컬럼을 명시적으로 작성한다.
